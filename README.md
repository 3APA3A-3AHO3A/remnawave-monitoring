# remnawave-monitoring

Мониторинг нод [Remnawave](https://docs.rw): графики в Grafana, алерты и ежедневная сводка в Telegram.

Ставится рядом с панелью одним `docker compose up -d`. На ноды ничего не устанавливается.

## Что умеет

**Алерты в Telegram** (приходят в чат или топик группы, со списком нод и сообщением о восстановлении):

| Алерт | Как определяется |
|---|---|
| Клиенты пропали с ноды | нода подключена к панели, час назад на ней были люди, а теперь почти никого. Похоже на блокировку IP |
| Нода не принимает клиентов | проверка подключается к хосту как обычный клиент и не может открыть страницу |
| WARP / Psiphon не работает | через ноду не открывается адрес, который её роутинг отправляет в WARP или Psiphon |
| Аутбаунд не отвечает | клиенты шлют запросы в аутбаунд (например, `psiphon-out`), а ответов почти нет |
| Нет метрик панели / не работает проверка | сломался сам мониторинг |

Отключение ноды от панели здесь не отслеживается: Remnawave сама шлёт об этом вебхук.

**Графики:** клиенты и трафик по нодам, трафик через каждый аутбаунд, результаты проверок хостов, нагрузка нод.

**Ежедневная сводка** в заданное время:

- что изменилось в GeoCheck (например, «Google видел ноду как FI, теперь RU»);
- сбои за сутки;
- пользователи;
- пик клиентов и трафик по каждой ноде.

К сводке прикладывается HTML-файл с полной таблицей GeoCheck по всем нодам.

## Как устроено

```
docker compose (всё слушает только 127.0.0.1)
 ├─ Prometheus      метрики панели (/metrics) и проверок, хранит 90 дней
 ├─ Grafana         графики + алерты в Telegram, наружу — через nginx
 ├─ xray-checker ×3 раз в 5 минут подключаются к хостам с тегом MONITORING:
 │                    «Xray жив», «WARP жив», «Psiphon жив»
 └─ reporter        список хостов для проверок, GeoCheck, ежедневная сводка
```

- Проверки хостов делает [xray-checker](https://github.com/kutovoys/xray-checker).
- GeoCheck запускает сама панель на каждой ноде, как кнопка GeoCheck в карточке ноды.
- `reporter` написан на Python без внешних зависимостей.

**Трафик.** Одна проверка — это установка соединения и крошечный ответ. Три проверки раз в 5 минут дают около 100 МБ в месяц на хост. GeoCheck раз в сутки — несколько МБ на ноду, трафик тратит сама нода.

## Требования

- Remnawave 3.3 или новее: нужны метрики Prometheus и GeoCheck через API.
- Docker с плагином compose на сервере панели.
- Telegram-бот и чат (или группа с топиками), куда бот может писать.

## Подготовка в панели

1. **API-токен.** Панель → Настройки → API-токены. Хватит прав только на чтение: ноды, пользователи, подписки (`raw`, `connection-keys`), `geocheck` и `geocheck-result`.
2. **Служебный пользователь**, например `monitoring`:
   - без лимита трафика и без срока окончания;
   - в сквадах, где есть проверяемые хосты.
3. **Тег `MONITORING`** на хостах, которые нужно проверять: по одному прямому хосту на ноду. Балансировщики, «автовыбор» и лимитированные хосты (LTE и т.п.) не отмечайте.
4. **Роутинг нод.** Проверки идут через настоящий конфиг Xray на ноде:
   - «Xray жив» открывает `https://www.google.com/generate_204`, он должен идти в `DIRECT`;
   - «WARP жив» открывает `https://icanhazip.com`, это домен из `geosite:category-ip-geo-detect`;
   - «Psiphon жив» открывает `http://ip-api.com/…`. В шаблон ноды нужно правило **выше** правила для WARP:
     ```json
     { "domain": ["domain:ip-api.com"], "outboundTag": "psiphon-out" }
     ```
   Адреса можно поменять в `.env` (`CHECK_URL_*`).
5. **Метрики.** В `/opt/remnawave/.env` должны быть заданы `METRICS_PORT`, `METRICS_USER` и `METRICS_PASS`.

## Установка

```bash
cd /opt/remnawave
git clone https://github.com/3APA3A-3AHO3A/remnawave-monitoring.git monitoring
cd monitoring
cp .env.example .env && chmod 600 .env
nano .env                       # заполнить токены, пароли, чат

docker compose up -d --build
docker compose exec reporter python -m rwmon check
```

`check` проверяет доступ к API панели, служебного пользователя и хосты, метрики в Prometheus и бота. Первые результаты проверок хостов появятся через 5–10 минут.

Пароли, в которых есть знак `$`, берите в одинарные кавычки: `GRAFANA_ADMIN_PASSWORD='pa$$word'`.

## Доступ к Grafana

Grafana слушает только `127.0.0.1:3300`. Есть два способа её открыть.

**Через SSH-туннель**, без домена:

```powershell
ssh -L 3300:127.0.0.1:3300 user@сервер-панели
# в браузере: http://localhost:3300
```

**Через nginx на поддомене.** Возьмите за основу пример [`nginx/grafana.conf.example`](nginx/grafana.conf.example). В нём уже есть ограничение частоты попыток входа. Сама Grafana тоже блокирует учётку после 5 неверных паролей. Регистрация и гостевой доступ отключены.

**Совет.** Для поддомена используйте wildcard-сертификат или Cloudflare-прокси. Отдельный сертификат Let's Encrypt попадает в публичные журналы, и сканеры находят «секретный» поддомен за минуты.

`GRAFANA_ADMIN_USER` и `GRAFANA_ADMIN_PASSWORD` применяются только при первом запуске. Потом пароль меняется в самой Grafana (профиль → Change password).

## Команды

```bash
docker compose exec reporter python -m rwmon check              # проверить настройки
docker compose exec reporter python -m rwmon links              # какие хосты проверяются
docker compose exec reporter python -m rwmon report --dry-run   # показать сводку, не отправляя
docker compose exec reporter python -m rwmon report             # отправить сводку сейчас
docker compose exec reporter python -m rwmon geocheck --send    # GeoCheck + сводка сейчас

docker compose logs -f reporter                                 # журнал
docker compose pull && docker compose up -d --build             # обновить
```

Если контейнер запустили позже времени сводки, сегодняшний GeoCheck и сводка выполнятся сразу после старта. Дальше — каждый день по расписанию.

## Настройки

Все настройки — в `.env`, у каждой есть комментарий в [`.env.example`](.env.example). Чаще всего меняют:

| Переменная | По умолчанию | Что это |
|---|---|---|
| `REPORT_TIME` / `GEOCHECK_TIME` | `15:00` / `14:30` | время сводки и GeoCheck, UTC |
| `GEOCHECK_EXCLUDE` | — | ноды (имена или теги нод), где GeoCheck не запускать |
| `GEOCHECK_BAD_COUNTRIES` | `RU,BY` | страны, которые подсвечиваются как проблема |
| `CLIENTS_DROP_MIN_AVG` / `CLIENTS_DROP_MAX_NOW` | `3` / `1` | порог алерта «клиенты пропали» |
| `OUTBOUND_TAGS` | `psiphon-out\|WARP` | аутбаунды для пассивной проверки |
| `CHECK_INTERVAL` | `300` | как часто проверять хосты, секунд |

После изменения порогов, чата или токена бота перезапустите Grafana: `docker compose up -d grafana` — значения подставляются в правила алертов при её старте.

Если меняете `CHECK_INTERVAL`, поправьте `for` у правил проверок в `grafana/provisioning/alerting/rules.yml`. Там стоит `6m`, то есть «две неудачные проверки подряд».

## Несколько панелей

На каждую панель ставится своя копия. Различается только `.env`: панель, чат или топик, домен Grafana.
