## 3.3.2 — 2026-11-26
**Сканеры: вердикт «CDN» — справка, а не блокировка**
- Вердикт cheburcheck «CDN Блок (16–20)» больше не считается блокировкой и не даёт тревоги «Адрес блокируют в сетях операторов РФ». Он значит, что у провайдера режутся соединения с зарубежными CDN (после первых 16–20 КБ), а сам адрес открывается. На дашборде и в отчёте он — справкой «CDN 16–20 КБ у N»; провайдер с таким вердиктом считается «открывает». Измерения, сохранённые раньше, пересчитываются сами — тревога по ним закроется после обновления.
- Тревога по сканерам остаётся для ТСПУ, блокировки по SNI и подмены DNS.

**Обновление:** `cd /opt/remnawave/monitoring && git pull && ./apply.sh`.

## 3.0.0 — 2026-11-26
**Проверка из РФ на пробах и итог по хосту**
- Хост проверяется так, как его видит клиент в России: пробы на серверах в РФ (`probe/`) подключаются к каждому хосту по адресу из подписки, как приложение клиента — включая Hysteria2 по UDP до прокладки. Список хостов проба берёт у мониторинга, результаты отправляет ему же (HTTPS на порт `[checks] ru_port`, 9116, пароль пробы, ключ сертификата мониторинга запоминается при установке).
- Сервер мониторинга проверяет хосты «через вход» (по адресу из подписки) и «на ноду» (напрямую) и по ним объясняет, где сломалось. Итог по хосту: работает / блокировка в РФ? / сломан вход / нода не отвечает / вход или блокировка. Хосты, которые ведут на сервер пробы (МСК-ноды), проверяет сервер мониторинга.
- Один алерт «Хост не работает» с причиной в сообщении вместо «Хост не принимает клиентов», «Хост не работает из РФ» и «Хост не открывается из РФ». Новый алерт «Проба из РФ молчит». Сводка, лента сбоев и `/status` в боте — по итогу.
- Дашборд собран заново: «Сейчас не работает», пробы из РФ, панели, сайты, блокировки РКН, таблица «Хосты» (итог, каждая проба, через вход, на ноду, проверки маршрутов) с историей, таблица нод снова со всеми колонками (с `[node_exporter]` — диск и conntrack), свёрнутые подробности.
- Убраны: проверка «Клиент из РФ» через хост-посредник (`[ru]`) и TCP-пробы хостов.

**Обновление**
1. На сервере мониторинга: удалите блок `[ru]` из `config.toml` (если есть), откройте порт 9116 для IP каждой пробы (`sudo ufw allow from <IP пробы> to any port 9116 proto tcp`), закрепите порты «через вход»: добавьте `30000-30999` в `/etc/sysctl.d/90-rwmon.conf` (`rwmon check` подскажет строку). Затем `git pull && ./apply.sh`.
2. На каждой пробе: `cd /opt/rwmon-probe && git pull && cd probe && sudo ./install.sh <IP сервера мониторинга>`. Блок `[[probe]]` в `config.toml` остаётся прежним.
3. `docker compose exec reporter python -m rwmon check` — пробы присылают результаты.

## 2.0.0 — 2026-11-24
**Проверки маршрутов из настроек**
- Блоки `[[check]]` в `config.toml`: что открыть через хост (`url`) и где должен оказаться выход — `egress = "other"` (не с IP ноды), `"node"` (с IP ноды), `egress_country` (страна), `egress_asn` (сеть). WARP, Psiphon, каскад в США — просто блоки настроек, а не код; проверок может быть до 8 или ни одной.
- Хосты для проверки выбираются по конфиг-профилю ноды (`profiles`, имя или UUID) или по названию (`hosts`); без них — все хосты с `MONITORING`. Нода хоста находится по IP или по `host_exit`. Новая нода профиля проверяется сама, теги на хостах не нужны. Для имён профилей токену нужно право Config Profiles: Get config profiles (без него работают UUID).
- Страну и сеть выхода reporter узнаёт по бесплатной базе DB-IP Lite: сам скачивает её раз в месяц в `data/geoip` и читает своим кодом, без зависимостей. Метрика `rwmon_exit_info`, новые алерты «‹проверка›: выход не там» и «‹проверка›: выход не с IP ноды».
- Правила алертов, дашборд, сводка и `rwmon links` собираются под набор проверок из настроек. Дашборд теперь собирает контейнер `config` при `./apply.sh`.
- **Старые настройки работают без правок:** без блоков `[[check]]` проверки WARP и Psiphon берутся из `url_warp` / `url_psiphon` с тегами-исключениями, как в 1.x; правила алертов те же (uid не меняются). Готовые блоки для нынешних проверок печатает `rwmon migrate-checks`.

**Контейнеры**
- Вместо трёх контейнеров `checker-xray`, `checker-warp`, `checker-psiphon` — один `checker`: по процессу xray-checker на каждую проверку, строки журнала помечены `[id проверки]`. Журнал: `docker compose logs -f checker`. Старые контейнеры `./apply.sh` убирает сам.
- Порты Xray проверок: «Подключение» — 21000+, каждая проверка маршрута — следующая тысяча; `rwmon check` подсказывает строку `ip_local_reserved_ports` под ваше число проверок.

- Хосты, которые панели делят через маппер UUID (например, ноды второй панели), снова проверяются из обеих панелей: если одна панель недоступна, проверки идут через другую.
- xray-checker получает готовые конфиги Xray вместо ссылок: настройки XHTTP (extra, xmux) доходят без потерь.
- Если в панели включён HWID, подписка запрашивается от постоянного устройства `rwmon-<id панели>` — у служебного пользователя появится одно устройство.
- Скрытые хосты и хосты, исключённые из типа «Xray JSON», в проверки не попадают — в журнале reporter видно, каких не хватает.
- API-токену больше не нужно право «Get connection keys by user id».

## 1.1.0 — 2026-10-23
**Алерты**
- «Хост не принимает клиентов» вместо «Нода не принимает клиентов»: проверяется именно хост (точка входа), у одной ноды их может быть несколько.
- В алерте видно, куда ведёт хост: «LTE 3 · OVRO → CDN 1 · FixErrorVPN». Нода находится сама, если адрес хоста совпадает с IP ноды в любой из панелей. Для хостов через Cloudflare или промежуточный сервер — настройка `host_exit` у панели: `host_exit = { "LTE 3" = "CDN 1" }`.
- Упали все хосты одной ноды — проблема на ноде; упал один — на пути этого хоста до неё.
