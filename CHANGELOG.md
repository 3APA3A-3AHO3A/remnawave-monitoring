# Changelog

Версии — по тегам `vX.Y.Z`. Релиз на GitHub собирается из раздела этого файла автоматически.

## 1.4.0 — 2026-11-24
**Алерты**
- «Трафик идёт мимо WARP» и «Трафик идёт мимо Psiphon»: адрес, который нода отправляет в WARP или Psiphon, открылся, но ответ пришёл с IP одной из нод панелей. Значит, запрос ушёл напрямую — обычно выход упал, а балансировщик переключился на прямой. Раньше такая проверка считалась успешной: IP выхода отличался от IP сервера мониторинга, и этого хватало.

**Проверки хостов**
- Третий патч xray-checker (`checker/exit-ip.patch`): метрика `xray_proxy_exit_ip{..., ip="…"}` — с какого IP проверка вышла в интернет. После обновления выполните `./apply.sh` — образ проверок пересоберётся.
- CI гоняет тесты xray-checker вместе с патчами.

## 1.3.0 — 2026-11-24
**Алерты**
- Все алерты уходят во все чаты (раньше сбой хоста шёл только в чат его панели): у каждой панели может быть свой админ, но видеть состояние всех серверов полезно каждому.
- Хост, общий для двух панелей (например, через маппер UUID), даёт в каждый чат одно сообщение вместо двух. Сообщение идёт от панели, которой принадлежит нода: по IP хоста среди нод всех панелей или по `host_exit`.
- У `rwmon_host` новые метки `owner` (панель-владелец ноды) и `primary` (одна строка на хост — по ней строятся алерты).

**Проверки хостов**
- Теги-исключения `MONITORING_NO_WARP` и `MONITORING_NO_PSIPHON`: ставятся рядом с `MONITORING`, если на ноде нет WARP или Psiphon. Эта проверка для хоста отключается, «Подключение» и вторая проверка остаются. Раньше на такой ноде проверка Psiphon открывала адрес, который уходил в другой выход (например, в WARP), и алерт приходил о чужой поломке. Имена тегов — `host_tag_no_warp` и `host_tag_no_psiphon` у панели.
- У общего хоста двух панелей проверка идёт, если она нужна хотя бы одной панели.
- У WARP и Psiphon теперь свои списки хостов (`/links/monitor-warp.txt`, `/links/monitor-psiphon.txt`). После обновления выполните `./apply.sh` — он пересоберёт настройки проверок.
- `rwmon links` показывает, у каких хостов проверка отключена.

## 1.2.0 — 2026-11-10
**Проверки хостов**
- Хосты берутся из подписки служебного пользователя в формате Xray JSON — так же, как её получают приложения, вместе с мапперами хостов. Base64 на хостах больше не нужен: его можно отключить, чтобы не отдавать UUID через «Fallback Base64».
- Хосты, которые панели делят через маппер UUID (например, ноды второй панели), снова проверяются из обеих панелей: если одна панель недоступна, проверки идут через другую.
- xray-checker получает готовые конфиги Xray вместо ссылок: настройки XHTTP (extra, xmux) доходят без потерь.
- Если в панели включён HWID, подписка запрашивается от постоянного устройства `rwmon-<id панели>` — у служебного пользователя появится одно устройство.
- Скрытые хосты и хосты, исключённые из типа «Xray JSON», в проверки не попадают — в журнале reporter видно, каких не хватает.
- API-токену больше не нужно право «Get connection keys by user id».

## 1.1.0 — 2026-10-23
**Алерты**
- «Хост не принимает клиентов» вместо «Нода не принимает клиентов»: проверяется именно хост (точка входа), у одной ноды их может быть несколько.
- В алерте видно, куда ведёт хост: «LTE 3 · OVRO → CDN 1 · FixErrorVPN». Нода находится сама, если адрес хоста совпадает с IP ноды в любой из панелей. Для хостов через Cloudflare или промежуточный сервер — настройка `host_exit` у панели: `host_exit = { "LTE 3" = "CDN 1" }`.
- Упали все хосты одной ноды — проблема на ноде; упал один — на пути этого хоста до неё.

## 1.0.0 — 2026-10-23
Первый релиз с номером версии. Всё, что было сделано до него:

**Мониторинг**
- Несколько панелей в одной установке: `config.toml`, у каждой панели свой чат и топик Telegram, одинаковые хосты разных панелей проверяются один раз.
- Проверки хостов через xray-checker (Подключение, WARP, Psiphon) со своим образом: поддержка Hysteria2 с Salamander `packetSize` и повторные попытки. Тег `MONITORING_LITE` — одна лёгкая проверка для LTE и хостов с лимитом трафика.
- Проба из РФ (blackbox exporter): видна блокировка IP хоста и недоступность сайтов изнутри России. Хосты на UDP в пробы не попадают.
- Проверка сайтов: код ответа, время, ключевое слово, срок сертификата; `any_status` для страниц с закрытым корнем.
- Здоровье панелей: задержка, память и время работы процессов; алерты «тормозит», «перезапустился», «ест много памяти».

**Алерты и сводка**
- Сообщения о восстановлении отдельно от продолжающихся сбоев, напоминания раз в час.
- «Аутбаунд не отвечает» на паузе: за выходами стоят балансировщики с резервом, реальный отказ ловят проверки WARP / Psiphon.
- Ежедневная сводка без дублей и минутных сбоев; в GeoCheck подсвечивается только новое со вчера.

**Дашборд**
- Таблица нод «всё в одной строке», карточка на каждую ноду, «Аутбаунды по нодам», «Сравнение нод», «Здоровье панелей», GeoCheck в Grafana.

**Проект**
- README в новом оформлении: баннер, пример алерта, схема, справка в сворачиваемых разделах; английская версия `README.en.md`.
- Автоматизация: Dependabot для образов Docker и GitHub Actions, еженедельная проверка новых версий xray-checker (PR, если патчи легли, иначе issue), релизы по тегу с текстом из `CHANGELOG.md`.
